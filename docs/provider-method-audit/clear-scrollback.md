## Matches

- **Registration & stdin (`cmd/gc-runtime-rex/main.go:109,277-279`):** Registered in `ops` as `"clear-scrollback": {1, "clear-scrollback <name>", opClearScrollback}`; `opClearScrollback` ignores `stdin` (matching `reads_stdin=False`) and ignores extra positional args beyond `args[0]`.
- **Success envelope (`cmd/gc-runtime-rex/main.go:176-180,348-350`, `cmd/gc-runtime-rex/dispatch_test.go` `TestClearScrollbackDeliveredExitsZero`):** On success, exits `0` with empty stdout and empty stderr; a live pane is cleared through exactly one `BlockClear`.
- **Missing or dead session (`## clear-scrollback` § Failure cases, § Conflicts):** a missing binding or an exited program answers exit `80` with one `{"outcome":"gone","detail":...}` line on stdout (`clear-scrollback: gone: ...` on stderr) and performs no clear. `ClearScrollback` resolves through `livePane` (`internal/provider/provider.go:688-703,834-850`) and `paneLookupOutcome` classifies the failure; `opClearScrollback` (`cmd/gc-runtime-rex/main.go:348-350`) returns it directly (GCREX-57). Pinned by `TestClearScrollbackMissingOrDeadIsGone` (`internal/provider/phase4_test.go`) and `TestClearScrollbackReturnsGoneForMissingOrDeadSession` (`cmd/gc-runtime-rex/dispatch_test.go`). `gc` v1.5.1 discards the error at its reconciler call sites, so gc is unaffected.
- **Liveness pre-check (`## clear-scrollback` § Inputs, § Failure cases):** `livePane` checks the bound block's program (`paneAlive`/`BlockProcess`, `internal/provider/provider.go:834-850`) before issuing the clear, so a dead program (`LastExit != nil`) answers `gone` instead of receiving `block.method clear` (GCREX-57).
- **No retry on transport/mid-call failure (`internal/rex/cli/cli.go:41-61,379-382,421-432`):** `Client.BlockClear` executes `rex api call block.method` once via `exec.CommandContext` with no retry; a dropped connection or lost reply exits `1`.
- **Buffered stdout / 64 KiB cap (`cmd/gc-runtime-rex/main.go:171-180`):** Output is buffered and nothing is written on failure; because `clear-scrollback` produces empty stdout on success, the 64 KiB cap never binds.

## Unverified

- **Live Rex `block.method clear` semantics (`internal/rex/cli/cli.go:380`, `docs/REX-CONTRACT.md:93`):** Whether Rex `clear` drops the visible screen as well as scrollback, how it affects subsequent `peek` (`format`) output and attached clients, and whether it errors or no-ops on a pane whose process has exited while the block still exists cannot be verified from this repo's Go code alone.
- **Non-`gc` consumers:** Whether any caller outside `gc` v1.5.1 relies on exit `80` `input-outcome` JSON or `GC_EXEC_DEADLINE_MS` for `clear-scrollback`.
