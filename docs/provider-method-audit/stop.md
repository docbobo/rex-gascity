# Method Audit: `stop`

**Verdict:** `deviations`

Audited against `docs/provider-herdr-method-io.md` (`## stop` and `## Shared RPP contract`).

## Matches

- **Registration & stdin** (`cmd/gc-runtime-rex/main.go:103,218-220`): registered as `"stop"` requiring 1 arg; `opStop` ignores `stdin` (`reads_stdin=False` equivalent) and writes nothing to `stdout` (empty stdout, well under 64 KiB cap).
- **Argument validation** (`cmd/gc-runtime-rex/main.go:149-152`, `dispatch_test.go:126,131`): missing or empty session name fails with exit 1, empty stdout, and usage message on stderr; extra positional args after `<name>` are ignored.
- **Idempotency / absent or vanished pane** (`internal/provider/provider.go:545-564`, `provider_test.go:150-161,259-269`, `teardown_test.go:114-125,137-149`): missing session or `rex.ErrNotFound` from `CloseBlock` succeeds with exit 0 and empty stdout/stderr; repeated `stop` is a no-op.
- **Per-name serialization** (`internal/provider/provider.go:532-534`, `internal/provider/lock.go:34-42`, `lock_scope_test.go:35-109`): exclusive per-name flock (`<stateDir>/locks/<name>.lock`) serializes `start` and `stop` for the same name without blocking other names.
- **Descendant reaping & survivor check** (`## stop` §Success output, §Failure cases, §Conflicts #1): `Provider.stop` (under `Stop`'s per-name and state flocks) snapshots the pane's foreground and every host process below it before `block.close` (`internal/provider/provider.go:777`; `internal/provider/reap.go:126`); ancestors only root the walk when Rex reports no foreground, and every captured name is the `ps` `comm` of that same snapshot. After the close it reads the pane again and unions what the pane still reports into that tree (`provider.go:791`, `unionProcs` at `reap.go:244`), tolerating `rex.ErrNotFound` (the normal no-pane case after a close) and ignoring a read error, so a process the pane started between the snapshot and the close is reaped rather than reported gone (`TestStopReapsAProcessThePaneStartedAfterTheSnapshot`). It then reaps the tree TERM -> 2 s -> KILL -> 2 s -> rescan (`reap.go:287`) and fails with exit 1 `stopped '<name>', but descendants may survive (the pane stays for a retry): <pid> (<name>), ...`, appending `: <signal error>` when a signal could not be delivered, and keeps binding, meta and activity (`provider.go:798-800`; `reap_internal_test.go` `TestStopFailsWhileDescendantsSurvive`, `TestStopSucceedsWhenTheSubtreeDies`). A signal failure does not abort the pass: the tree is still signalled in full, so one unsignalable process cannot shield the rest (`signalAll`, `reap.go:211`; `TestStopKeepsSignallingAfterASignalFailure`). Each survivor is rendered pid plus command name; `splitProcessRow` (`reap.go:101`) takes the command name as the rest of the `ps` row, so a name with spaces stays whole. A pane that vanishes between `Resolve` and `BlockProcess` (`rex.ErrNotFound`) is the no-pane case, so the stop proceeds to the close and succeeds. An unreadable process table fails the whole stop while the pane is still open, so the retry starts from a fresh snapshot; no table read happens without a live pane (`TestStopAlreadyDeadSessionScansNoProcessTable`). A foreground that is a leaf narrows the snapshot to that process, so the agent's other children are not captured. Difference from herdr-core: the tree is the pane's reported processes, not an instance token, so attribution is a snapshot rather than a token sweep.
- **Incarnation cleanup & error preservation** (`internal/provider/provider.go:553,558-564,575-591`, `incarnation_test.go:16-149`, `teardown_test.go:127-135`): `clearIncarnations` removes all metadata and activity in both live-pane and no-pane paths; a non-`ErrNotFound` `CloseBlock` error returns exit 1 and preserves the binding, metadata, and activity for retry.

## Unverified

- **Live SIGTERM / 30 s cancellation timing** (`cmd/gc-runtime-rex/main.go:48-50`, `internal/provider/lock.go:73-94`): exact elapsed shutdown timing when `gc` sends SIGTERM (and SIGKILL after 2 s) while `stop` is blocked in `withFlock` or `CloseBlock` is not verified in a live run.
- **Rex `block.close` descendant behavior and the unreadable-table claim** (`internal/provider/reap.go:126`, `provider.go:777-790`): whether the close kills the process group, a detached descendant, or neither is not established in a live run; the provider reaps regardless. That an unreadable `ps` table fails the stop is asserted from the code path, not observed against a live Rex: no live run has produced a table-read failure during `stop`.
- **Rex `Name` vs `ps` `comm` matching** (`internal/provider/reap.go`, `living`/`sameProcess`/`sameProgram`): `living` treats a captured process whose row no longer matches as gone, so a mismatch turns a live process into a false success. A live run on 2026-11-20 (macOS 25.6, BSD `ps`) recorded the pairs: Rex foreground `name: node` with `argv0: pi` → `ps -o comm=` `pi` (pids 80230, 67401, 89149); ancestor `name: fish`, `argv0: -fish` → `-fish` (pid 51330); ancestor `name: login` → `(login)` (pid 51329). Darwin's `comm` is argv[0], and a Rex pane runs its command with argv0 set to the launched command, so the snapshot takes each captured name from the same `ps` table `living` reads, with Rex's `Name` only a fallback for a reported pid the table lacks (`paneSubtree`; `TestStopMatchesTheProcessTableNameNotRexsName`). Identity is the pid plus its `ps` `lstart` from the same snapshot: a renamed or exec'd descendant still matches and is reaped (`TestStopKeepsAProcessThatRenamedItself`), while a recycled pid has a different start time and is neither signalled nor reported (`TestStopDoesNotSignalAReusedPid`); the name is only the fallback when a read printed no `lstart`. Still unverified: GNU `ps` on Linux reports the executable's task name truncated to 15 characters — it would truncate identically on both reads, but no live Linux Rex run has recorded a pair.
