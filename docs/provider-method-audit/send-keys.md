**Verdict:** `deviations`

Audited against `docs/provider-herdr-method-io.md` (`## send-keys` and `## Shared RPP contract`).

## Deviations

## Matches

- **Registration & stdin** (`cmd/gc-runtime-rex/main.go:108,269-275`): registered as `"send-keys"` requiring 1 positional arg (`<name>`) plus optional `[keys...]`; `opSendKeys` ignores `stdin` (`reads_stdin=False` equivalent).
- **Success output & activity floor** (`cmd/gc-runtime-rex/main.go:169-173,269-275`, `internal/provider/provider.go:730,736`, `internal/provider/activity.go:126-133`, `internal/provider/input_test.go:173-188`): exits 0 with empty stdout and empty stderr, and records `InputAt` via `noteInput` after `SendKeys` succeeds so `get-last-activity` reflects key input.
- **No retry on transport/mid-call failure** (`internal/rex/cli/cli.go:41-61,363-370`, `cmd/gc-runtime-rex/main.go:164-167`): `Client.SendKeys` invokes `rex send-key -s <sid> -b <bid> -- <keys...>` once with `exec.CommandContext` and never retries; any error or cancellation exits 1.
- **`gc` v1.5.1 key set** (`internal/provider/keymap.go:30-54,64-78`, `internal/provider/keymap_test.go`, `internal/provider/input_test.go`): translates all keys `gc` v1.5.1 sends (`Enter`, `Up`, `Down`, `Escape`, `C-u`) to Rex syntax (`enter`, `up`, `down`, `esc`, `ctrl+u`).
- **Key grammar & pre-validation** (`## send-keys` §Inputs Key grammar, §Failure cases; GCREX-43): `translateKeys` (`internal/provider/keymap.go:64-78`) translates every key before the pane lookup via `translateKey` (`keymap.go:80-100`), so an unspellable key rejects the whole call before any Rex call. It matches herdr-core: exact-case `tmuxKeys` incl. `BTab`/`PPage`/`NPage`/`F1`–`F12` (`keymap.go:30-54`); `C-`/`M-`/`S-` only while `len(rest) > 2`, on a table name or a single lower-cased literal char, in typed order (`peelMods`, `keymap.go:136-156`); literal text split char-by-char (`literalKeys`, `keymap.go:177-193`). `Provider.SendKeys` validates before the pane lookup and `classifyInput` at `stageValidate` (`internal/provider/input.go:84`) turns a `KeyRejectedError` into a `rejected` outcome; `handlerExitCode` (`cmd/gc-runtime-rex/main.go:318`) renders exit 80 and one `{"outcome":"rejected","detail":…}` line.

## Unverified

- **Rex `rex send-key` atomicity & key support** (`internal/rex/cli/cli.go:363-370`): whether the external `rex` CLI rejects an entire multi-key call atomically if one key is invalid, and how it handles `shift+<letter>` or unknown names, cannot be settled from this repo's Go code.
- **Race between the lookup and `rex send-key`** (`internal/provider/input.go:154-175`, `internal/rex/cli/cli.go:50-55`): if the pane closes between the lookup and `rex send-key`, `Client.run` returns `rex.ErrNotFound`. `inputPolicies[send-keys].sendNotFound` is empty, so the failure stays unclassified and the race exits 1 instead of the typed `gone`.
